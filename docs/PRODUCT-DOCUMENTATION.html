Product Guide

Mahaverse Product Documentation

Mahaverse is an ABA practice management platform used to manage staff, clients, clinical programs, schedules, session notes, data collection, billing configuration, claims, reports, users, and role-based access. It centralizes the operational and clinical flow from intake and setup through service delivery and revenue-cycle follow-up.

Product Overview

The product is split into two connected applications: Mahaverse, the main practice-management workspace, and Maha Launchpad, an intake/onboarding experience. Users access modules from the left sidebar, and available menu items depend on their role and permissions.

Operational management Create staff, clients, providers, locations, users, and permissions.
Clinical workflow Configure domains, programs, targets, behaviors, session notes, and data collection.
Scheduling and billing Schedule sessions, complete notes, finalize rendered hours, preview claims, and track reports.

Terminology

Use these terms consistently while working in the product.

Client The recipient of ABA services. Client records include demographics, insurance, authorizations, guardian details, documents, clinical assignments, and notes.
Staff A clinical or operational employee record. Staff records are used for provider details, certifications, availability, assignments, scheduling, and documentation.
User A login account with a role and permissions. A user account is separate from a staff record.
Session A scheduled appointment linked to a client, provider, supervisor, authorization, date/time, place of service, and rendered hours.
Session Notes SOAP documentation, clinical notes, service metadata, signatures, and completion state for a client/session date.
Data Collection Skill acquisition, behavior-reduction, and related clinical measurements recorded during service delivery.
Configure Data Organization-level clinical libraries such as domains, programs, targets, prompts, behaviors, and behavior categories.
Client Configure Data Client-specific assignment of clinical programs, targets, domains, and behaviors that appear in data collection.
Authorization Insurance approval details tied to billing codes, date ranges, units or hours, and billing readiness.
Rendered / Ready to Bill Session states that indicate services were delivered and can move into billing or claims review.
CMS-1500 Professional claim form used for insurance billing preview and claim output.
RBAC Role-based access control that governs module visibility and action permissions.

Authentication

Authentication controls login, token storage, password reset, and the user's initial entry into Mahaverse or Launchpad.

Access

Login Flow

Open Mahaverse and enter email and password.
The system validates credentials and stores the signed-in user, auth token, and token expiry in the browser.
Permissions are loaded for the user and the dashboard opens with role-appropriate navigation.
If the login was started from a protected Launchpad link, the user can be redirected into the requested Launchpad route after authentication.

Password Reset Flow

Choose forgot-password or reset-password from the login experience.
Request an OTP for the account email.
Verify the OTP.
Set the new password and return to login.
Expired token. If the saved token is expired, the user is logged out and must sign in again.
Permission refresh. Permissions can change server-side; refresh or sign in again if module visibility does not match recent Role Access changes.
Environment dependency. API calls depend on the configured base URL for the deployed backend environment.
Logout. Signing out clears the active session and returns the user to the login entry point.

Roles and Access

Mahaverse uses role-based access control. The sidebar only shows modules the signed-in user can view, and some actions such as creating, archiving, deleting, or editing records require additional permissions.

Admin Full administrative access, including role access, users, staff, clients, setup data, and operations.
BCBA Clinical oversight workflows, including clients, programming, schedules, session notes, and data review.
RBT Direct service workflows, commonly focused on schedules, session notes, and data collection.
Biller Billing, claims, payer payments, reports, service code setup, and revenue-cycle views.
Parent / Client Limited portal-style access where enabled by the administrator.
Planner Scheduling and planning workflows where granted.
If a user cannot see a module or button, check Role Access first before assuming the module is missing.

Recommended Setup Sequence

The smoothest onboarding path is to configure foundational records before creating clients and sessions. This prevents missing options while scheduling or completing billing details.

  1. Create roles and users, then verify each role has the correct permissions.
  2. Create manage-data records: locations, facility types, treatment types, providers, service codes, diagnosis codes, document types, and payer payments.
  3. Create clinical configuration: domains, programs, targets, prompts, behavior categories, and behaviors.
  4. Create staff records, including professional details, certifications, availability, assignments, and documents.
  5. Create client records, including demographics, contact information, guardians, insurance, authorizations, assigned clinical programs, availability, and documents.
  6. Create sessions from Scheduling, then complete data collection and session notes after service delivery.
  7. Review billing and claims once sessions are rendered and documentation is complete.

End-to-End Flows

New Client to First Billable Session

Create the client profile with demographics, contacts, guardian, insurance, documents, and notes.

Assign client-specific domains, programs, targets, and behaviors.
Create or verify the staff provider record with availability and active status.
Schedule the session using the correct client, provider, supervisor, authorization, place of service, and location.
Complete data collection, SOAP notes, clinical notes, rendered hours, and signatures.
Review the rendered session in billing/claims and preview or generate the claim output.

New Hire to Product Access

Use Launchpad for offer letter, onboarding form, signatures, and required document collection where applicable.
Create a Mahaverse staff record with professional details, certifications, documents, assignments, and availability.
Create a user account for login access and assign the correct role.
Use Role Access to confirm the role has required module and action permissions.
Have the new user sign in and verify that their sidebar and allowed actions match their job responsibilities.

Staff Module

Create and manage provider/staff records used for scheduling, supervision, assignments, and documentation.

People
Add Staff Edit Staff Archive / Restore Documents Availability

How to Create a Staff Record

Open Staff. From the sidebar, select Staff.
Start a new record. Click Add Staff.
Complete Personal Information. Enter first name, last name, email, phone, SSN if required, address, and emergency contact.
Complete Professional Information. Select staff type such as RBT, BT, BCBA, or BCaBA; set status; add NPI, hire dates, education, assigned supervisor, assigned clients, and job title.
Add Certifications. Add one or more certifications with type, number, issue date, expiration date, and status.
Set Availability. Select available days, start/end times, and service location preferences such as home, clinic, school, or community.
Upload Documents. Add staff documents such as licenses, background checks, or other configured document types.
Save. Submit the form. The record appears in the active staff list if the status is active and it is not archived.

Cases Covered

Edit staff. Use the edit action on a staff row, update any tab, and save.
Archive staff. Use archive options to move a staff member out of the active list. Archived staff can be restored from the archived view.
Search and filter. Search by name, staff ID, or certification number; filter by staff type and status.
Document viewing. Uploaded documents can be viewed from the staff detail area when a document path is available.
Scheduling readiness. Staff must be active and not archived to appear as available providers for scheduling.
Supervisor/client assignments. Assign supervisors and clients so clinical responsibility is visible and permission scopes can be enforced.

Clients Module

Create and manage client intake, demographic, contact, insurance, authorization, clinical configuration, and documentation data.

Clinical Records
Add Client Edit Client Session Notes Data Collection Configure Data Archive / Restore

How to Create a Client

Open Clients. From the sidebar, select Clients.
Start a new record. Click Add Client.
Complete Personal. Add name, date of birth, gender, preferred language, workflow status, active flag, waitlist status, and location.
Complete Contact. Add phone, email, appointment reminder preference, and one or more service addresses such as Home, Telehealth, Office, School, or Other.
Add Guardian and Emergency Contact. Enter parent/guardian details, relationship to insured, emergency contact name, phone, email, and relationship.
Add Insurance. Add Primary, Secondary, or Tertiary insurance, subscriber details, claim settings, signatures on file, insured address, payer details, and insurance notes.
Configure Client Data. Assign clinical domains, programs, targets, and behaviors that should appear during data collection.
Add Authorizations. Add authorization number, status, start/end dates, service/billing code, units or hours, provider, treatment type, facility type, and notes.
Set Availability. Add weekly availability windows used by scheduling and planning.
Upload Documents and Notes. Add insurance, intake, clinical, service, or miscellaneous documents, plus client notes and other information.
Save. The client becomes available for scheduling if active and not archived.

Client Workflow Statuses

Client records support the following workflow statuses:

  • New
  • Benefits Verification
  • Prior Authorization
  • Client Assessment
  • Pending Authorization
  • Initial Authorization
  • Active Treatment
  • Reauthorization

Cases Covered

Edit client. Use the edit action on a client row to update any tab, insurance, authorizations, documents, or clinical configuration.
Archive client. Archive a client to remove them from the active list. Restoring makes the record active again.
Search and filter. Search across client fields and filter by workflow status or active/inactive state.
Multiple addresses. Add more than one service location when the client receives services in multiple settings.
Multiple insurances. Use Primary, Secondary, and Tertiary insurance tabs when a client has more than one payer.
Authorization status. Authorizations are Active or Inactive. Scheduling uses active authorizations that match the selected billing code.
Session notes shortcut. Open Session Notes directly from the client row for documentation tied to a date.
Data collection shortcut. Open Data Collection from the client row to record skill acquisition and behavior data.

How to Create a Location

Open Manage Data, then choose Locations.
Click the add-location action.
Complete General Office Information: Tax ID, office phone, time zone, start/end time, location name, description, and status.
Complete Facility Service Location details for claim Box 32: facility type, NPI, name, address, city, state, and zip.
Complete Billing Provider details for claim Box 33: taxonomy code, billing NPI, provider name, billing address, city, state, and zip.
Save. The location becomes available in client, scheduling, and billing workflows where applicable.

Reference Data Cases

Add/edit setup records. Use each setup screen to maintain active values for dropdowns and billing configuration.

Document upload consistency. Document Types determine the options users see when uploading client or staff files.

Scheduling and Sessions

Create, view, edit, cancel, and delete scheduled sessions. Scheduling connects clients, providers, authorizations, locations, and session notes.

Service Delivery

How to Create a Session

Open Scheduling. From the sidebar, select Scheduling.
Choose a calendar date. Use Today, Month, Week, Day, or list-style views, then click Add Session or a date cell.
Select the client. Only active, non-archived clients should be used for new sessions.
Select provider and supervisor. Choose an active provider and, when needed, a supervising provider.
Choose date, time, and timezone. Enter start and end time. Scheduled hours calculate from the time range.
Select place of service and location address. Use the correct service setting for operational and billing accuracy.
Select billing authorization. Choose a billing code backed by an active client authorization. The system validates that the selected authorization belongs to the client.
Add a quick note. Use quick notes for scheduling context or special instructions.
Choose recurrence if needed. Set a repeating schedule with frequency, weekly days, and ending rules.
Save. The session appears on the calendar and can be opened for viewing, editing, session notes, or data collection.

Session Statuses

  • Scheduled: Default status for upcoming and active appointments.
  • Rendered: Used when services have been documented and are ready for billing workflow.
  • Ready to Bill: Indicates session documentation/billing data has been finalized for revenue-cycle processing where enabled.
  • Cancelled: Used when a scheduled session is cancelled with a reason.

Cases Covered

Edit one session. Open the session and edit date, time, provider, authorization, notes, or location details.
Edit recurring sessions. For recurring appointments, choose whether to update one occurrence or the recurring set.
Cancel session. Cancel from the edit flow and record a cancellation reason. Recurring sessions can support single or recurring cancellation mode.
Delete session. Delete is permission-gated and usually restricted to scheduled sessions that are not rendered or ready to bill.
Provider conflict check. The scheduler checks for local provider schedule conflicts before saving.
Missing authorization. If billing code selection fails, refresh client data or verify the client has an active matching authorization.
Session notes shortcut. Use the notes action on a calendar item to open notes for that exact client/date/session.
Filters. Use location and staff filters to narrow the calendar to specific operational views.

Session Notes and Data Collection

Record clinical data, SOAP notes, service details, signatures, and rendered-session information.

Clinical Documentation

How to Complete Data Collection

Open a client or scheduled session and select Data Collection or Session Notes.
Confirm the session date. When opened from Scheduling, the modal uses the linked session date.
In Skill Acquisition, record trials or values for assigned client programs and targets.
In Behaviors, record behavior-reduction data and relevant behavior counts or measurements.
Save progress so entered data is stored with the session note payload.

How to Complete Session Notes

Open the Session Notes tab set.
Complete Overview: session date, start/end time, people present, caregiver, service location, diagnosis, service codes, and administration write-up.
Complete SOAP Entry: subjective, objective, assessment, and plan.
Complete Clinical Notes: add clinical observations and any required service narrative.
Complete Signatures: collect employee and guardian signatures where required.
Save the note or complete/finalize it when documentation is ready for billing.

Cases Covered

Future sessions. Future-dated sessions are protected from completion. Save behavior may be allowed, but complete/finalize is blocked until the session date is valid.
No scheduled session found. Notes can still load client configuration; scheduling metadata may be blank if no appointment exists for the date.
Configured data missing. If skill targets or behaviors are not visible, confirm they are assigned on the client Configure Data tab.
Saved notes. Reopening a date loads previously saved notes and data collection entries.
Billing handoff. Completed notes can update rendered/billing-ready session data depending on the session workflow.
Signatures. Employee and guardian signatures include names and signature dates for documentation compliance.

Administration

How to Create a User

Open Users from the sidebar.
Click Add User.
Enter email, password, first name, and last name.
Select a role: admin, BCBA, RBT, biller, parent, planner, or client.

Cases Covered

Role Access

Administrators use Role Access to grant or remove module and action permissions by role.

Security

How to Update Permissions

Open Role Access. This is available to administrators with user-management permission.
Choose the application scope, such as Mahaverse or Launchpad.
Select the role you want to edit.
Search or expand modules to find the relevant permission group.
Turn permissions on or off. Some permissions support scoped choices such as off, self, or all.
Review the permission summary and save changes.
Permission changes affect navigation visibility and action availability. After saving, users may need to refresh or sign in again depending on their current session.

Maha Launchpad

Maha Launchpad is the intake/onboarding area connected from the product switcher in the sidebar header.

Intake

Launchpad focuses on collecting onboarding information through a guided form and supporting backend workflows such as SSO login, OTP verification, offer acceptance, document upload, Google Drive integration, reminders, and RBAC.

Typical Flow

Open the product switcher from the sidebar header and choose Maha Launchpad.
Start or continue the guided form.
Complete step-based intake sections such as location, emergency contact, documents, and related form details.
Submit the form and upload required attachments where prompted.
Administrators can review submissions, signatures, reminders, and document storage workflows.

Common Operational Cases

A provider does not show in Scheduling. Confirm the staff record is active, not archived, and has a provider/staff type appropriate for scheduling.
A client does not show in Scheduling. Confirm the client is active, not archived, and has the required authorization/setup data.
Billing code cannot be selected. Confirm the client has an active authorization whose billing code matches the intended service code.
Targets are missing in data collection. Confirm the targets exist in Configure Data and are assigned to the client in the Configure Data tab.
A module is missing from the sidebar. Check the user's role and role-access permissions for that screen.
Documents are not categorized correctly. Review Document Types in Manage Data and ensure the uploader selects the correct type.
Claims are incomplete. Review client insurance, authorizations, provider setup, locations, diagnosis codes, service codes, and completed session notes.
Need to preserve history. Prefer archive, restore, inactive, or status changes over deleting records used by historical sessions, notes, or claims.

Product Caveats

Navigation model. Main Mahaverse modules are controlled by view state and local storage rather than deep-linked routes. Launchpad uses route-based pages.
Billing overview. The Billing Overview screen includes illustrative metrics and invoice-style UI; Claims is the operational claim-review area.
Sessions placeholder. The standalone sessions view is not the primary live documentation flow. Scheduling plus Session Notes is the active session workflow.
Parent portal. Parent/client portal behavior may be limited or placeholder depending on deployment and permissions.
Environment split. Production and test backends may have different base URLs and database wiring. Confirm the configured environment before debugging missing data.
Historical records. Prefer archive, inactive status, or restore flows over deleting records that may be referenced by sessions, claims, documents, or reports.
